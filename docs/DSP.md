# Original DSP design and limitations

Open Room implements its own sweep generator, transfer-magnitude estimator and linear-phase FIR designer. It does not reproduce Dirac's optimization, mixed-phase correction, bass management, microphone calibration database, filter encoding or NAD upload protocol. A target curve is a desired frequency response; an FIR file is a local convolution filter. Neither is a proprietary NAD/Dirac device filter.

## Measurement

The generated exponential sine sweep has phase

`phase(t) = 2π f_start T / log(f_end/f_start) × (exp(t log(f_end/f_start)/T) − 1)`.

The start and finish use 20 ms cosine fades. The allowed requested peak level is −90 to −3 dBFS, with a conservative application default recommended. Digital level does not determine sound pressure: the player's volume, speaker sensitivity and distance do. Begin with low player volume and increase only enough for a useful signal above the background noise.

The reference and complete microphone recording are DC centered, zero padded to the same FFT length and transformed. For each excited bin, the regularized estimate is

`H(f) = Y(f) conjugate(X(f)) / (|X(f)|² + λ)`

with `λ = max(|X|²) × 10⁻⁸`. The reported magnitude is the reference-power-weighted RMS of `|H|` in a roughly 1/12-octave band. Curve positions are logarithmically spaced from 20 Hz to the lesser of 20 kHz and 95% of Nyquist. Essentially unexcited bins are omitted. This is a full-record magnitude estimate, not an impulse-response or phase reconstruction.

A fixed playback/capture delay multiplies the transfer by a phase factor and therefore does not need peak alignment. This property requires the entire sweep and the acoustic tail to be present in the recording. Begin recording before playback and leave several seconds after playback. Capturing a cut-off sweep cannot be repaired by this estimator. Different player and microphone sample clocks can drift, invalidating the transfer estimate; no clock-drift correction or uncertainty estimator is implemented. A swept sine is required for meaningful broadband results, even though the function accepts general arrays.

The measurement includes microphone response, microphone gain, speaker, room and player processing. An arbitrary input device can record audio, but it is not automatically a calibrated measurement microphone. Use a known microphone, consistent gain and placement. Disable automatic gain control and other microphone processing where possible. Microphone response calibration is supported as described below, but it does not establish absolute sound-pressure level. This DSP module does not separate distortion from the linear response. The application's session layer can average multiple captured positions; their playback and capture gain settings must stay consistent. Reflections remain in the measurement. Ambient noise, clipped capture, truncated reverberation and varying playback volume can create misleading curves.

### Microphone calibration

`import_calibration` accepts whitespace-separated frequency in Hz and microphone response error in dB, with an optional numeric phase column. It accepts blank lines, `#`, `;`, `*` and `//` comment lines, and recognizes common UMIK-style quoted `Sens Factor =...`, `Sensitivity =...`, serial-number metadata and frequency/gain column headings that explicitly name Hz and dB. Recognized sensitivity headers are deliberately ignored: absolute SPL calibration needs the microphone's gain chain and a reference pressure, not just the response-error table. An optional phase column is validated and ignored because this designer corrects magnitude only. CSV, unfamiliar prose headers and malformed numeric lines produce an error instead of a partly interpreted calibration.

`calibrate` subtracts the log-frequency-interpolated microphone response error from every measured point: positive calibration dB means the microphone over-reads and is subtracted. The calibration table must cover the entire measured frequency range; Open Room refuses to invent calibration outside the known range. The file must use this response-error convention. If a supplier provides correction gains instead, invert those gains before importing. Use a calibration for the microphone's serial number, orientation and measurement angle. Calibrate individual position captures before averaging; apply calibration once, and retain the raw capture for repeat processing.

Microphone input gain and player volume still set an arbitrary overall dB offset. A target should be anchored to a representative measured level or the measurement normalized explicitly before comparing its shape with a nominal 0 dB curve. Frequency-response calibration alone does not remove this offset.

## Filter design

The designer interpolates measurement and target gain linearly in log frequency. Within the curtains it takes `target_dB − measurement_dB`, limits boost to the requested 0–12 dB and cuts to 24 dB, and tapers the correction over 1/6 octave at each curtain with a raised cosine. Both curtains must be inside the measured frequency range. Session averaging uses only the shared measured range of the included captures, and each capture must span 500–2000 Hz for normalization. Missing measured bass or treble is never invented by holding the endpoint. Frequencies outside the curtains receive no relative correction. Deep narrow nulls should not be filled with large boosts: repositioning the speaker or microphone is usually more useful.

The desired amplitude is converted to a Hermitian spectrum with a linear phase delay of `(taps − 1)/2` samples. An inverse FFT produces a real impulse, which is truncated with a Blackman window. The returned filter is normalized using a dense FFT of the windowed coefficients so its sampled peak frequency gain is at most unity. This gives overall attenuation when boosts are requested; the attenuation also applies outside the curtains. This does not guarantee against every possible time-domain peak: leave playback headroom and check the actual convolution output for clipping.

Odd filter lengths, such as 4097, give an integer delay and an exact delayed impulse for a unity target. Even lengths use a half-sample delay and force zero response at Nyquist, as required for an even-length symmetric FIR. Short filters cannot resolve low-frequency room modes accurately. At 48 kHz, 4097 taps introduce approximately 42.7 ms latency; 8193 taps introduce approximately 85.3 ms. Linear-phase correction can introduce pre-ringing. No phase or timing correction is inferred from magnitude-only measurements.

## Target interchange

Export uses the public text target grammar: `BREAKPOINTS`, frequency/gain pairs, disabled `HPSLOPEON` and `LPSLOPEON` directives, the conventional cutoff/order fields, and `LOWLIMITHZ`/`HIGHLIMITHZ` curtains. The point values are supplied by the user or generated by Open Room. Target imports validate point ordering, finite values and curtains, and reject enabled high/low-pass slopes because the original FIR designer does not implement their proprietary semantics. A target import into official Dirac software is the supported handoff for applying correction to a NAD device; the official application must perform its own measurement/filter generation and transfer.

## Verification

Unit tests cover sweep bounds and fades, delayed synthetic room-response recovery against a known two-tap transfer, a unity odd-length impulse, even-length symmetry, passband cuts and uncorrected curtain regions, bounded boost with shared gain normalization, curve round-tripping, calibration header/phase parsing and recovery of a known response using log-frequency interpolation, and invalid input rejection. These are algorithm checks, not evidence of acoustic calibration or NAD filter transfer. A physical speaker/microphone measurement and an actual NAD application handoff remain separate validation steps.
# Conditional original native multirate DSP

The staged original native designer uses a 75-tap common low-pass and two factor-4 down/up stages. Its low FIR operates at the main rate divided by 16. The high path is a complementary high-pass before its cell FIR. A high-only filter with a zero low branch therefore loses bass in this model.

The first original design has matched linear-phase group delay: 1023 high taps (511 samples), 129 low taps (64 low samples = 1024 main samples), and 513 additional high samples. Common reconstruction contributes another 370 samples, giving 1394 samples total. All cell FIR arrays are padded to the observed native sizes without changing the active impulse delay.

Native correction is limited to 20–500 Hz and validated against the complete 16-phase model. If the short linear-phase design cannot reproduce the requested shape within 1 dB, the designer tries an original, longer minimum-phase design. It does not smooth the requested curve, change its boost/cut bounds, or relax the accuracy gate. A feature that neither design can resolve is rejected with the worst error and frequency.

The longer design derives a causal minimum-phase impulse from the desired log magnitude using the real cepstrum: retain the zero/quefrency and Nyquist terms, double positive quefrencies, zero negative quefrencies, transform back and exponentiate. It uses 960 active low-rate taps, with a cosine taper over the final 64 taps to control truncation, preceded by 64 low-rate zero samples. This fills the native 1024-tap low payload. Its high spectrum is constructed from the **same truncated low filter's complex response at matching physical frequencies**, rather than independently minimizing phase at two different sample rates. Above the low-rate Nyquist frequency the high correction returns to unity. The high spectrum receives 511 samples of reference delay, is transformed and windowed to 1023 taps, then padded to 1024; the existing 513 extra high samples are retained.

Both paths therefore retain the 1394-sample unity/reference delay. Minimum-phase correction adds frequency-dependent phase, so 1394 is not a claim of constant group delay at every corrected frequency. This design is an original magnitude correction strategy; it is not Dirac's proprietary mixed-phase optimizer.

`NativeDesign.design_strategy` identifies the selected method and `linear_phase_rejection` records why a fallback was needed. Every rate's `ModelCheck` records the worst shape error and frequency, plus matching requested and achieved **correction** response points. Both correction curves exclude uniform headroom attenuation so their difference measures FIR approximation error directly. The achieved correction is the complete simulated multirate response, including both branches; it is not a measured acoustic response. The unchanged sampled 1 dB shape and −70 dB alias gates are checked before normalization, with normalized response and peak bounds reported afterward. An additional 5-degree phase gate checks the high/low correction phase difference where both complementary paths contribute at least 0.1 in magnitude, and a regression test verifies that misaligned branches fail that check.

The FIR approximation error is distinct from the room's remaining deviation from the full user target. `target_response` and `predicted_room_response` show that full target and the measured room shape plus modeled correction, over measured frequencies only. `max_target_error_db` and `worst_target_hz` report the remaining full-target difference within the curtains; `max_full_band_target_error_db` includes the measured frequencies outside them. Intentional boost/cut bounds and curtain transitions can leave a substantial target residual even when the FIR faithfully implements the bounded request. Predicted room curves also exclude uniform headroom attenuation; subtract `attenuation_db` to include its overall digital level effect. These remain conditional predictions from stored room magnitude graphs, not new acoustic observations.

Joint headroom normalization uses the induced time-domain peak bound over every output phase. Both branches and all three main rates receive identical attenuation. This is conservative and can reduce overall level substantially even for a cut-only target, but it preserves relative curve shape and complement balance. A broad synthetic 6 dB cut around 200 Hz required about 4.43 dB of overall attenuation in the original model; its sampled shape error stayed below 0.32 dB across all rates. Narrow-feature validation and clipping bounds are different checks.

When combining independent speaker designs, `align_speaker_headroom` applies further attenuation to match the most attenuated speaker. Raising another speaker's gain to match would undo its peak bound; the encoder must use the extra-cut helper before serialization.

Nine native tests cover every resampling phase, actual simulated branch outputs, gain bounds, speaker matching, the unchanged synthetic narrow feature resolved by the longer design, explicit requested/achieved error metadata, full-room-target residuals despite accurate bounded correction, phase misalignment, and rejection of a sub-hertz feature beyond available resolution. The native prototype and FIR algorithms are independently authored, with no proprietary taps or correction optimizer. No private measurement fixture is embedded in the source.

A separate read-only validation used an existing private 18-response session, with nine included positions per speaker and 30–500 Hz curtains. The short linear-phase method failed its unchanged gate. The longer design's worst checked shape error stayed below 0.46 dB across all three sample rates with the saved cut-only setting, and below 0.45 dB with an independently evaluated 3 dB boost limit. Shared stereo peak headroom required approximately 9.00 dB and 11.12 dB of overall attenuation respectively. These are offline results against stored response graphs, not hardware or acoustic validation. The private session was not modified.

This implementation remains conditional: the M10's behavior when given a different common low-pass and its implicit high complement have not been observed. The staged model is not a hardware-tested filter encoder, and a successful RPC transfer would not establish acoustically correct correction. See the source-location and firmware-gap ledger in the native transfer addendum.
