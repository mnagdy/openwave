# Audio measurement

The audio module lists currently connected microphone and output devices. On macOS, it reads CoreAudio device properties without creating AudioUnits or opening streams; CPAL opens the stream only for authorized capture or playback. Duplicate device names receive a numbered suffix across the full device list. Refresh the list after connecting or disconnecting equipment. The listing shows the current sample rate and channel count; capture validates the selected channel and rate against the device metadata. Channels are numbered from zero in the Rust API.

Recording captures a selected microphone channel to a mono float32 WAV with a maximum duration of 180 seconds. Device errors, missing permission, missing channels, invalid samples, and timeouts are returned as errors. Import accepts float32 and 8/16/24/32-bit PCM WAV files, using the first channel of multichannel recordings. The peak level and clipping flag describe captured digital samples. A flat or silent recording can still indicate the wrong microphone or routing.

Local measurement requires an explicitly selected output connected to the NAD's audio input, such as a wired Mac audio interface feeding an M10 analog input. The NAD does not become a CoreAudio output merely because it is on the network. An AirPlay or Bluetooth output may have latency, processing, or clock drift that makes a measurement unreliable; use wired routing and disable processing that is not part of the intended measurement chain. Select one output channel per measurement and set the amplifier volume manually before starting. The API rejects signals above -20 dBFS, but the amplifier's gain determines the acoustic level.

Measurement opens microphone and output streams at the same exact supported sample rate. It emits half a second of silence, the supplied sweep, and two seconds of silence. Capture retains startup latency and an additional short tail, so the response analysis must locate and align the sweep. Independent hardware clocks can drift; this implementation does not calibrate or compensate clock drift. Session analysis supports microphone frequency-response calibration; absolute sound-pressure calibration is not implemented. A clipping flag uses a peak threshold of 0.999 and is a warning, not proof of analog distortion.

The packaged app includes `NSMicrophoneUsageDescription` and explicitly requests microphone access before capture. Its two-second microphone check uses memory only and does not play a signal or save a recording. Apple documents this authorization flow in [requestAccess](https://developer.apple.com/documentation/avfoundation/avcapturedevice/requestaccess(for:completionhandler:)). Unit tests verify float WAV roundtrips, channel selection and PCM scaling, invalid sample handling, and input validation without accessing audio hardware. Actual microphone capture and NAD playback require connected hardware and are verified separately.

`capture_with_action` supports a signal started by a separate device controller. It authorizes microphone access, selects the requested channel and exact rate, starts capture, and waits at most two seconds for the first finite input buffer before calling the supplied action. The action must enforce its own deadline of at most 90 seconds (the native controller bounds its asynchronous work and cleanup to approximately 80 seconds); a synchronous closure cannot be forcibly interrupted by the audio helper. The helper itself opens no output and sends no network commands. It retains startup samples and then records the requested tail after the action returns (normally two seconds), requiring both elapsed time and the corresponding number of new samples. Input errors, non-finite samples, a two-second loss of input during the tail, a full buffer, and the overall 180-second capture limit cause an error. Any return drops the input stream. The requested tail must fit within the remaining recording limit. These limits apply after stream start; CoreAudio construction and start calls do not expose cancellable deadlines.


For native network measurement, `resample.rs` converts the independently reconstructed 48 kHz reference to the selected microphone's current rate (8–192 kHz). The conversion preserves physical frequency and duration, applies Fourier-domain anti-aliasing for downsampling, and handles even/odd Nyquist bins. Numerical tests check amplitude/phase, DC, duration and alias rejection. This does not compensate clock drift between the microphone and amplifier.
